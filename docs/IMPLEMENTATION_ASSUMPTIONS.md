# Implementation assumptions and baseline conflicts

No assumption below adds product scope. DOC-000 defines precedence as DOC-001, then
DOC-002, DOC-003, and the remaining architecture/implementation documents.

| ID     | Ambiguity or conflict                                                                                                                                 | Current decision                                                                                                                                                                                                                   |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| IA-001 | DOC-001 marks Login P1; DOC-002 and DOC-014 treat authentication/login as P0.                                                                         | The approved Sprint 1 clarification resolves Login into Sprint 1. Implement the exact auth routes with a Demo-only identity adapter and server-enforced sessions; this does not change Login priority elsewhere in the baseline.   |
| IA-002 | DOC-001 uses RAM critical ≥92%, Ping critical ≥120 ms, and packet loss critical ≥8%; DOC-003 uses ≥90%, ≥100 ms, and ≥5%.                             | Domain rules must use DOC-001 values unless a Change Request amends the baseline. No threshold logic is implemented in Sprint 0.                                                                                                   |
| IA-003 | DOC-001 defines `Open → Acknowledged → Investigating → Resolved`; DOC-003, DOC-005, and DOC-006 omit `Investigating`.                                 | The shared Sprint 0 status union includes `INVESTIGATING` under DOC-001 precedence. Persistence/API representation must be reconciled before Alerting implementation.                                                              |
| IA-004 | DOC-001 and DOC-003 specify different Network Health Score deductions, and packet loss, ping, and degraded-device ratio lack complete formulas.       | DOC-001 fixed deductions and classification boundaries govern. Sprint 1 calculates only offline-device, critical-alert, and warning-alert deductions; it marks the formula incomplete and does not interpolate unresolved factors. |
| IA-005 | DOC-001 names top-level `features/domain/server/simulation`; DOC-004 defines top-level `modules`; DOC-008 defines per-module layers.                  | Use DOC-004 `modules/` as the repository boundary and DOC-008 layers inside each module. This preserves the separation required by DOC-001 without duplicating parallel structures.                                                |
| IA-006 | DOC-001 names WebSocket/Socket.IO; DOC-003 and DOC-004 permit WebSocket or SSE and require fallback snapshot/polling.                                 | No provider or transport is selected in Sprint 0. REST remains the future source of truth; a later ADR must select the transport using hosting constraints.                                                                        |
| IA-007 | DOC-000 calls Sprint 0 “database foundation,” while the assignment prohibits production database integration and unused placeholder dependencies.     | Reserve and document `prisma/`; defer schema/client packages until a sprint uses and validates them. Core database-aligned enums are established now.                                                                              |
| IA-008 | DOC-014 references IDs absent or renamed elsewhere (`PRD-DETAIL-001`, `PRD-SIM-001`, `PRD-RT-001`, `PRD-RBAC-001`) and maps alert IDs inconsistently. | Track canonical IDs from DOC-001, DOC-002, and DOC-003. Treat DOC-014 aliases as traceability defects requiring correction, not new requirements.                                                                                  |
| IA-009 | DOC-001 proposes an implementation stage sequence while DOC-000 provides the explicit Sprint 0–7 roadmap used by the assignment.                      | Use DOC-000 for sprint planning and DOC-001 for scope/priority precedence. No scope is removed; sequencing differences are recorded.                                                                                               |
| IA-010 | The approved UI lists shadcn/ui, but it is a source-component workflow rather than a required runtime package.                                        | Establish compatible Tailwind tokens and project-owned primitives; add only components actually used in later sprints.                                                                                                             |
| IA-011 | Sprint 1 requires authentication before production identity infrastructure or account persistence is in scope.                                        | Use three fixed fictional server-side Demo identities with bcrypt cost-12 hashes. Credentials are intentionally public for repeatable RBAC testing; the adapter is explicitly not production-ready.                                |
| IA-012 | Signed stateless cookies make logout easy without adding forbidden persistence, but do not provide targeted server-side revocation.                   | Use an eight-hour signed HttpOnly cookie. Logout expires the browser cookie; copied tokens remain valid until expiry unless `AUTH_SECRET` is rotated. This limitation is accepted for Demo use only.                               |
| IA-013 | Dashboard metrics are required before telemetry, simulation, persistence, and realtime sprints.                                                       | Treat counts, traffic, alerts, events, timestamp, and trends as fixed deterministic Demo fixtures. They must never be described as live monitoring data.                                                                           |
| IA-014 | The approved Sprint 1 role name is `NETWORK_ENGINEER`, while an earlier foundation union used `ENGINEER`.                                             | Adopt `NETWORK_ENGINEER` across the canonical role schema and tests so deterministic accounts match the approved RBAC matrix.                                                                                                      |
| IA-015 | A local memory login limiter is useful for Demo smoke/security checks but resets on restart and is not shared across instances.                       | Keep a five-attempt/15-minute process-local limit and document it as a Demo safeguard only. Production abuse controls remain deferred with production identity.                                                                    |
